# ПР №2 — этап 4. Обратные зависимости

Конфигурационное управление, вариант 14. Формат пакетов: JavaScript (npm).

Находит прямые и транзитивные обратные зависимости итеративным DFS.
В локальном режиме область поиска — весь тестовый репозиторий.

## Сборка и запуск

Python 3.10+, только стандартная библиотека. Сборка и установка не нужны.
Команды выполняются из папки этого этапа:

```sh
./run.sh --test --repository examples/reverse.json --package D --version 1.0.0
```

Прямой запуск: `python3 -B src/__main__.py` с теми же параметрами.
Windows: `py -B -m src`. Справка: `./run.sh --help`.
`python3 -B demo.py` запускает локальный пример без сети.

## Все настройки

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Имя npm-пакета; в тестах A–Z | Обязательно |
| `--version` | Точная версия SemVer X.Y.Z | Обязательно |
| `--repository` | URL registry или путь к тестовому JSON | https://registry.npmjs.org |
| `--test` | Читать локальный тестовый репозиторий | Выключен |
| `--output` | Имя выходного PNG; рядом создаётся `.mmd` | graph.png |
| `--max-depth` | Максимум рёбер от корня, 0 — только корень | 10 |
| `--stage` | Выбрать доступный этап 1–4 | 4 |
| `--target` | Целевой пакет обратного поиска на этапе 4 | Значение package |

До этапа 5 имя изображения только проверяется; файл не создаётся.
Ошибки аргументов завершаются кодом 2, ошибки данных/сети — кодом 1.
Проверяются имя, версия, URL, тестовый путь, расширение и каталог PNG,
неотрицательная целая глубина и доступный номер этапа.

## Примеры и ошибки

```sh
./run.sh --package is-odd --version 3.0.1
./run.sh --package is-even --version 1.0.0
./run.sh --package ansi-styles --version 4.3.0
./run.sh --package is-odd --version wrong
./run.sh --package is-odd --version 3.0.1 --max-depth -1
./run.sh --package is-odd --version 3.0.1 --output invalid.svg
```

Последние три команды демонстрируют ошибки. На этапе 1 первые три
выводят настройки; на этапе 2 — прямые зависимости; далее — результат
соответствующего этапа.

## Проверка

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты автономны и работают без сети. Реальный registry требует интернета.

## Получение зависимостей

`repository.py` читает JSON registry через urllib, без npm и сторонних
библиотек. Учитываются `dependencies` указанной версии. Для каждой
зависимости выбирается наибольшая удовлетворяющая версия; доступны
точные версии, `^`, `~`, сравнения, x/*, частичные версии, `||`,
диапазоны через дефис и dist-tags. Prerelease исключаются без явного
указания соответствующего prerelease-диапазона.

Область модели — обычные runtime dependencies. devDependencies,
peerDependencies, optionalDependencies и правила установки платформы
не моделируются. Git, URL, file, workspace и npm aliases выдают ошибку.
Это анализатор графа, а не полная реализация установщика npm.

## Граф и тестовый режим

`graph.py`: DFS через стек, без рекурсии. Узел — пара (имя, версия),
поэтому разные версии общего пакета не конфликтуют. Корень имеет
глубину 0. Узлы на границе включаются, их зависимости не запрашиваются.
Если DFS позже находит более короткий путь, узел раскрывается повторно
с новым запасом глубины. Циклы сохраняются, повторная работа ограничена
улучшением глубины. Лимит — 1000 узлов.

Тестовый JSON: `{"A": ["B"], "B": []}`. Все узлы должны быть объявлены,
имена состоят из заглавных A–Z. `--version` задаёт общую версию узлов.

```sh
./run.sh --test --repository examples/diamond.json --package A --version 1.0.0
./run.sh --test --repository examples/cycle.json --package A --version 1.0.0
./run.sh --test --repository examples/chain.json --package A --version 1.0.0 --max-depth 1
./run.sh --test --repository examples/shortcut.json --package A --version 1.0.0 --max-depth 2
```

Ромб обходится A → B → D → C. Цикл A → B → C → A завершается.
Есть также одиночный узел, цепочка и граф с коротким альтернативным путём.

## Обратные зависимости

`reverse.py` разворачивает рёбра и выполняет DFS со стеком, учитывая
максимальную глубину. Цель не включается в результат даже при цикле.
В тестовом режиме анализируется весь файл, поэтому для D в reverse.json
находятся C, A и B, хотя они недостижимы при прямом обходе из D.

Для реального registry область поиска — граф корня `--package`.
Registry не предоставляет полный список всех потребителей каждого
пакета. `--target` позволяет искать потребителей внутри загруженного
графа; без него цель совпадает с корнем, и ответ обычно пуст.
Результат не претендует на поиск по всему npm.

```sh
./run.sh --stage 4 --test --repository examples/reverse.json --package D --version 1.0.0
./run.sh --stage 4 --test --repository examples/cycle.json --package A --version 1.0.0
./run.sh --stage 4 --package is-odd --version 3.0.1 --target is-number
```

## Исходники

config.py — параметры; versions.py — SemVer; cli.py — управление этапами; __main__.py — точка входа; repository.py — registry; test_repository.py — тестовый JSON; graph.py — DFS и граф; reverse.py — обратный поиск.
Код находится в `src/`, проверки — в `tests/`.
